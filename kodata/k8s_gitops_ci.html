k8s-gitops-ci

A GitOps CI Engine in a Single Go Binary

Overview

In a mature GitOps environment, everything is a pull request. When you combine human engineers, automated dependency bots like Renovate, and AI coding agents, PR volume explodes. The human review queue becomes the bottleneck — reviewers get "YAML fatigue" looking at hundreds of plausible-looking manifests a day, and that is precisely when semantic bugs slip through.

AI raises the ceiling on output, but it also introduces the "plausibility trap": an LLM writes YAML that looks perfect — right kind, right fields, perfect indentation — and then it dies at admission (a Kustomize patch that silently applies to nothing, a network config that doesn't parse, a selector that doesn't match its own template). An AI agent is only as productive as its feedback loop, so CI has to answer in seconds, deterministically, every single time.

The CI this replaced couldn't keep up. It was a multi-task Tekton pipeline where every linter spun up its own pod attached to a shared PVC (minutes of pod-startup and volume-attach overhead before a single file was read), with logic buried in Bash scripts that could not be unit-tested. The Timeline below traces how it got there and how it was rewritten.

CI is the universal safety net. k8s-gitops-ci is that net: an open-source, org-agnostic single Go binary. It resolves exactly what a PR changed, lints it, builds only the Kustomize/Helm overlays the change affects, runs a registry of Kubernetes compliance checks against the result, and posts one unified report back on the PR. The same command runs on a laptop with no remote and no PR.


One Binary, Not a Pile of Pods
  • Kustomize builds run through the native Go SDK and Helm charts render through the native chart loader — no helm binary, and no kustomize binary for builds.
  • kubeconform runs as a library, with its schemas embedded in the binary and pinned to a specific upstream commit — no CDN, no network at run time, and a reproducible archive build.
  • Raw manifests are deduplicated by content hash, so a resource shared by many overlays is checked once and the finding is attributed to every file that carries it.
  • It shells out only where no library exists (git, kustomize for edit fix, shellcheck, golangci-lint, markdownlint, prettier, kyverno, the forge CLIs, and the AVP plugin) — always with an explicit argument slice, never a shell.
  • The payoff in wall clock: what used to take minutes now takes seconds.
App-Aware Overlay Detection
  • The naive check — "does the changed path contain overlays/?" — either rebuilds all dependent overlays or, worse, rebuilds zero and tells you the PR is fine.
  • The engine finds the app root you touched and distinguishes a cluster-specific change from a shared base/component change.
  • For shared changes it walks each overlay's actual Kustomize reference graph (resources/components/bases) and keeps only the overlays that genuinely reference the changed piece — the safety of "check everything that could be affected" at the cost of "check only what is affected."
  • Ghost Patch Detection: a Kustomize patch that targets nothing doesn't error — it silently does nothing. The engine cross-references every patch against the rendered base and flags the orphans.
  • Kustomize Fix: a dry-run of the real kustomize edit fix; when it would change something, the report contains the exact fix command to copy and paste.
Runtime Validation — Beyond the Schemas
  • The OpenAPI schemas kubeconform validates against carry almost no value-level constraints: across all 1,373 built-in schemas there are no pattern checks, no minimums or maximums, and no uniqueness rules. The schema for metadata.name is literally "string or null", so a 400-character name passes.
  • So the Kubernetes API server's own admission validation is ported into Go, function by function and organized per API group, plus a family for the NetworkAttachmentDefinition CRD and OVN's semantic rules.
  • Every ported rule cites the upstream function it came from, and task ci fetches those functions and fails if upstream changed them — so a Kubernetes change surfaces as a loud, specific re-port.
  • Runtime findings are always blocking and never exemptable: the cluster itself would reject those manifests.
Security by Default
  • PR-triggered CI is not a security boundary. A PR's own test.sh hook is untrusted input — a malicious PR could otherwise rewrite what its own CI runs.
  • Fail-closed hook sourcing: on a pull request, test.sh is read from the trusted target branch, not from the PR. The working-tree copy is trusted only on a push, after merge. A /hook-test comment opts a PR in to testing its own hook; restricting who may post it is delegated to the CI trigger's policy.
  • Transparent exemptions: annotations sit on the manifest next to the field they excuse and show up in the PR diff; repo-wide EXEMPTIONS selectors must be merged first. A malformed exemption parses to zero exemptions plus a blocking error, so a typo can never silently over-exempt.
  • The hard line: CEL rules, broken JSON, missing-registry image FQDNs, and every runtime check are not exemptable. You can turn a check off — you can't lie about a finding.
  • Rendered YAML written to disk is mode 0600, since it is the one artifact that could carry a resolved secret.
Org-Agnostic by Design
  • The repo is a generic engine: no org names, cluster names, or company domains in the code. Organizations import it as a Go module and compile a thin wrapper binary — no forks required.
  • Org-specific behavior is injected at startup through a provider.Providers seam: branding, comment-marker policy, secret-backend hints, and cluster/project identity. Exported override variables cover compile-time data.
  • Every step has a stable ID that can be turned on or off with --enable-checks / --disable-checks. Kyverno is off by default because there is no generic policy bundle that suits every org.
One Unified Report
  • Instead of spamming the PR, the engine updates a single collapsible markdown comment (or prints to the console without --comment).
  • Every section records its status, and skipped sub-checks are shown — a linter never silently disappears.
  • Applied exemptions render in an audit table, labeled by whether they apply to directly modified files or pre-existing ones, so new drift can't hide behind an old waiver.
  • The comment ends with a ready-to-copy CLI command so any engineer or AI agent can reproduce the run locally.
  • Presented as "Robust CI as a Safety Net" at KubeCon (Salt Lake City) — a 30-minute tag-team session with Jennifer Weir weaving high-level GitOps philosophy with a deep dive into the Go architecture.

Technology Stack

  • Language: Go.
  • In-process: Kustomize SDK, Helm chart loader, kubeconform (embedded schemas), CEL.
  • External tools: shellcheck, golangci-lint, markdownlint, prettier, kyverno, kustomize (for edit fix).
  • Forges: GitHub and GitLab.
  • Delivery: Tekton Pipelines-as-Code for the repo's own CI, GitHub Actions for multi-arch images, GoReleaser for releases.
  • Packaging: Go module, release binaries, and a multi-arch UBI 10 Minimal container image on GHCR.
  • Testing: table-driven suites with false-positive guards, a non-blocking live-PR replay, and upstream-citation verification.

Pipeline Flow

The binary runs a fixed sequence of phases. Cheap, decisive gates run first, independent work fans out across goroutines (bounded by CPU count), and everything funnels into one report. The repo's own CI is deliberately tiny — one Pipelines-as-Code PipelineRun with two parallel tasks — because the heavy lifting lives in the binary, where it is testable. The lint task runs the tool against the repo itself.

  1. PR Validation (forge API only, cheap): PR title convention, unsigned commits, PR checklist.
  2. Changeset Resolution — determine exactly which files this PR touches.
  3. Large File Check and YAML Syntax — two sequential gates, since everything downstream assumes parseable files.
  4. Linting — fanned out: markdownlint, prettier, golangci-lint, shellcheck (which also lints Bash embedded in Tekton task scripts and container commands), and raw-manifest kubeconform.
  5. Static Checks — fanned out: config sort order, starting-CSV sanity, and the scaffold README status table.
  6. Build YAML — scaffold validation, then the affected overlay set (app-aware, not a bare path match) is rendered through the native Kustomize/Helm engines (with AVP where configured), followed by Kustomize Fix and Ghost Patch Detection.
  7. Post-Build Validation — against the rendered output: kubeconform, CEL, runtime validation, NAD validation, the resource-compliance registry, and Kyverno (opt-in). Every finding is classified as blocking (direct) or warning-only (external).
  8. Unified Report — one PR comment (or console output) assembled from every phase.

The Dual Pass: Raw vs. Rendered

Some checks must run against the raw committed file — a vault-plugin placeholder like <vault:secret> is a legitimate state in git; it resolves at deploy time, not at review time. Other checks must run against the final rendered output, after Kustomize generators and patches have done their mutations. The engine runs both passes and guarantees each changed manifest is judged by exactly one of them — so you never get the same finding twice, and you never validate a state that never actually deploys.

Findings are change-aware: a finding on a resource the PR itself changed is blocking; a finding that only surfaced because a shared base or component the PR touched feeds that resource is warning-only. Introducing a new policy therefore can't break legacy code the PR didn't touch.

Checks at a Glance

There are about a hundred registered checks, grouped into two families. The complete, current ID list lives in the CI.md reference rather than being duplicated here.

  • Resource compliance (12): namespace declaration, Pod Security Admission labels, RBAC read-only aggregation and wildcard bans, ClusterRoleBinding sanity, ArgoCD sync-options, image digest pinning and explicit registry hosts, named ports, pod-spec defaults (securityContext, resources), unresolved placeholders, and cluster-identity copy/paste.
  • Runtime validation (~90): 1:1 ports of the API server's admission rules across apps, batch, core, networking, policy, RBAC, storage and more, plus the NetworkAttachmentDefinition/OVN family — each citing the upstream function it was ported from and verified on every CI run.
  • Gated steps: linters, CEL, Kustomize Fix, scaffold checks, AVP, and Kyverno each have a stable ID for --enable-checks / --disable-checks.

Modes

Mode Command Changeset Source
Full pipeline pipeline --url <repo> --pr <n> PR's changed files via the forge API
Local PR check pipeline --revision <sha> --target-branch <branch> git diff <target>...<revision>
Working-tree diff test Uncommitted changes in the current tree
Directory scan test [dirs...] / test --dirs Every file under the given paths
Full repo scan test --all Every file, every overlay — ignores git state entirely
Ad-hoc overlay build build-yaml --app <a> --cluster <c> Targeted: the given app's base/ + overlays/<cluster> only

test accepts the same scoping and check-enablement flags as pipeline, so a failing CI run reproduces on your laptop with no remote and no PR.

Install
go install github.com/ArthurVardevanyan/k8s-gitops-ci/cmd/k8s-gitops-ci@latest
Usage
# Full CI pipeline: PR checks, linting, static checks, resource compliance.
k8s-gitops-ci pipeline --url https://github.com/<org>/<repo> --pr 123

# Run every validator against the working tree (no PR/remote needed).
k8s-gitops-ci test ./kubernetes

# Full-repo scan, printing only failing sections.
k8s-gitops-ci test --all --quiet

# Build rendered YAML for a specific app/cluster overlay.
k8s-gitops-ci build-yaml --app my-app --cluster my-cluster

Timeline / Process

  • Shell Scripts — “Does It Build?”

    December 2022 – February 2023

    GitOps overlays were multiplying across many apps, and nothing verified that they still rendered before ArgoCD tried to sync them.

    • December 2022: First per-app test.sh: a loop over */overlays/* running kustomize build.
    • December 2022 – February 2023: test.sh rolled out app by app. Runs were local, serial, and per-app; there was no pipeline yet.
    • Key Tech: Kustomize, Bash.
  • Pipelines-as-Code & the First Real CI

    February – March 2023

    The scripts moved into a Tekton pipeline triggered by Pipelines-as-Code on every pull request.

    • February 2023: First PipelineRun. It ran every test.sh via find | bash, with no change filtering. AVP rendering added (kustomize build | argocd-vault-plugin generate -).
    • March 2023: Change detection: gh pr diff --name-only maps changed files to the overlays they affect. First PR comment output through gh pr comment.
    • March 2023: Helm rendering path added (helm template with the overlay's values).
    • March 2023: kubeconform schema validation as its own task; rendered YAML is handed over through a shared workspace volume.
    • March 2023: kubeconform becomes blocking.
    • Key Tech: Tekton, Pipelines-as-Code, Kustomize, Helm, AVP, kubeconform, gh.
  • Hardening & Plumbing

    April – November 2023

    No new check categories; this phase was about keeping the pipeline reliable.

    • June 2023: Restricted git-clone task variant introduced.
    • Through 2023: Pinned pipeline images, repeated kubeconform image and schema refreshes, storage-class updates, and cleaner PR comment output.
  • The Lint Suite & Stricter Gates

    November 2023 – December 2024

    With rendering and schema validation in place, attention turned to the quality of everything else in the repo.

    • November 2023: markdownlint, prettier, and shellcheck added to the pipeline.
    • December 2023: pre-commit hooks: gitleaks, shellcheck, checkov, markdownlint, prettier. yamllint was configured but never enforced.
    • January 2024: Conventional-commit check added to pre-commit.
    • September 2024: Stricter shellcheck through a repo-wide .shellcheckrc.
    • December 2024: CI now fails when test.sh is missing or invalid.
    • December 2024: Pipeline standardizes on a single shared builder image.
    • Size: about 3,000 lines of bash across ~106 test.sh files, plus an inline pipeline of ~490 lines.
  • Reusable Tasks & a Dedicated Overlay Repo

    2025

    Pipeline logic was copy-pasted per repository. It was extracted into versioned, reusable tasks.

    • March 2025: New overlay repository with a full inline-bash pipeline: build-yaml, changed-file loop over test.sh, markdownlint, prettier, shellcheck, kubeconform.

    • July 2025: First Go code: a standalone OVN-aware NetworkAttachmentDefinition validator called from the bash pipeline. It is the direct ancestor of today's k8scni checks.
    • July – August 2025: Prettier path/extension fixes and a build-yaml 300-file limit fix.
    • October 2025: Lint-only pipeline: a fast path that skips builds and kubeconform. Follow-ups skip non-Kubernetes YAML and add Kustomize support to kubeconform.
    • October – December 2025: A steady cadence of kubeconform image and JSON-schema updates and new CRD schemas.
    • Key Tech: Tekton tasks, GoReleaser, kubeconform, a first Go validator.
  • test-utils.sh — Bash at Its Limit

    • January 2026: Scaffold drift detection: do overlays still match the templates they were generated from? Also what-changed logic for push events.

  • The Go Rewrite

    June 2026

    The multi-task bash pipeline was replaced by a single Go binary, with no shared volume needed to pass state between tasks.

    • June 2026: Rewrite pull request opened as a breaking change.
    • June 2026: The Go pipeline runs in shadow (non-blocking) mode alongside the bash pipeline.
    • June 2026: Rewrite merged: ~28k lines added, ~20k of them Go and ~8.9k of those tests.
      • 23 validation steps: large-file, YAML syntax, markdownlint, shellcheck, prettier, golangci-lint, kustomize-fix, startingCSV, scaffold status and drift, build-yaml, kubeconform, placeholder, ClusterRoleBinding namespace, RBAC, sync-options, image SHA pinning, cluster identity, pod-spec defaults, PSA labels, and Kyverno policies.

      • Embedded schemas and policies: kubeconform schemas and Kyverno policies compiled into the binary.
      • Compatibility shim: a no-op test-utils.sh was injected so existing test.sh hooks ran unchanged during migration.
      • Same day: GoReleaser fixes, drift-detector fix, and promotion to a blocking >= 1.0.0 release.
    • June 2026: Bug-fix blitz (CRD scope, annotation checker, ghost-patch warnings) and the first parallelism pass: linters run concurrently with ErrorInSection tracking.
    • June 2026: Namespace-scoped CR check, dependency-update automation, and license scanning onboarded.
    • June 2026: More parallelism: static checks launched together, per-app/per-cluster goroutine pools, a --concurrency flag, and a per-phase timing summary.
    • June 2026: Selective builds: only overlays whose Kustomize reference chain reaches a changed path are built, with a safety valve. Merge-queue support and a readability refactor.
